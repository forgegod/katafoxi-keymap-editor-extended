# CAP-001 — Firmware keymap editing

**Status:** partial
**Primary surface:** human

## Behaviour

- All built-in behavior choices retain descriptive native titles with `Ctrl+click: docs`. Ctrl or Meta-click opens known help with `_blank` and `noopener,noreferrer`, without selection, confirmation, binding/definition/color changes or document/history mutation. `&uc` links the third-party [urob README](https://github.com/urob/zmk-unicode/blob/main/README.md), `&inc_dec_kp` links [Encoder Rotation](https://zmk.dev/docs/features/encoders#rotation), and `&studio_unlock` links [Studio Unlock](https://zmk.dev/docs/keymaps/behaviors/studio-unlock). Other built-in destinations remain unchanged. Ordinary pointer/Space selection stays staged; Enter applies an already complete binding.
- Arbitrary named hold-taps with document-proven metadata expose [hold-tap family help](https://zmk.dev/docs/keymaps/behaviors/hold-tap), explicitly not their exact definition, timing or children. Existing Homerow/Autoshift preset links retain this family destination and ordinary staging. Unknown two-parameter bindings, familiar-looking labels, choice-only `holdTap` hints, opaque/unproven definitions and legacy `&reset` remain unlinked.
- Every rendered per-layer Layer + RGB selection chip exposes the [ZMK macro pattern](https://zmk.dev/docs/keymaps/behaviors/macros#layer--underglow-color), explicitly not exact editor recipe documentation. Its native title retains “release restores black”; the upstream example uses another release color. Ctrl/Meta help precedes selection, color memory and preset/recipe staging, preserving unchanged or changed drafts and existing redo. Adjacent HSB swatches remain color controls without help hints or gesture interception. Named-family and recipe chips retain wrapping, keyboard focus and main-scroll reachability in light/dark at 1280×720 and 360×640.
- Unicode Character / Input mode switch controls use 12px inherited UI type and 22px compact tabs; scalar/search fields and native selects use 24px token-themed controls. Pressed tabs use an accent border/wash, tab/alias hover uses accent, and keyboard focus uses a 2px accent outline. Alias glyphs and wrapping 11px code identifiers remain distinct. Fields wrap at narrow width (360×640) in light/dark. At 1280×720 and 360×640 in light/dark, the unfiltered catalog shares the KeyEditor's main vertical scrollport rather than introducing a nested alias scroller; controls and their text are reachable without horizontal cropping. Apply/Cancel stay outside that scrollport. Invalid scalar input retains the visibly disabled Apply action and readable error.
- The Unicode picker displays a named polite status for the editor-selected English profile: compatible, incompatible with missing/remapped service-key diagnostics, or unavailable when its column/table is absent. It updates when that profile or table changes, independently of national layouts, English-column visibility and cached display glyphs.
- Unicode compatibility warnings do not block editing or valid Apply. Invalid scalar input still blocks Apply; Cancel retains the original binding, and unchanged Apply preserves alias and opaque tokens. The picker explains that `&uc` requires a compatible English layout active in the OS while used; a national layout may remain installed, but the editor cannot detect, select or modify the OS active layout.
- GitHub ignores matching named JSON without a `layouts` member and keeps the editable binding-count rectangle when no applicable geometry remains. Present invalid `layouts` or malformed layout JSON block loading; the picker identifies the failed layout file, not the selected `.keymap`. Shared-layout precedence and the stricter Local boundary follow [CAP-002](CAP-002-keymap-sources-and-persistence.md).
- Clipboard and GitHub expose Layout discovery for a loaded document. Without supplied geometry, a reviewed catalog can preview a bounded ZMK transform or physical layout; explicit board/shield/revision and ambiguous-candidate type/label selection never guesses from a filename or overrides firmware chosen declarations. Preview includes source/catalog revisions, attribution, transform spelling, offsets, sensor association and binding origins.
- Accept layout requires acknowledgement of unverified firmware compatibility and catalog provenance. It changes session display geometry only, not the loaded geometry baseline, firmware bindings, history, host state or files. Discard restores the loaded geometry, including after Clipboard Copy. Electrical inference is not measured physical geometry; physical metadata is only source-declared. Scheme coordinates remain serialization slots. Cancel and failed/stale actions preserve the live board. See [source and export boundaries](CAP-002-keymap-sources-and-persistence.md).
- Clicking a firmware layer slot opens a staged KeyEditor. A complete binding can be applied; cancel leaves that key unchanged. Catalog choices include keys, modifiers, layer references, device commands and Unicode input. Bluetooth choices include `BT_DISC` with the documented default profile indexes `0`–`4` and parameterless `BT_CLR_ALL`; RGB underglow choices include parameterless `RGB_ON` and `RGB_OFF`.
- Parameterized stock behavior choices wrap onto visible rows inside the KeyEditor, including at 360×640, rather than clipping the last choices horizontally. Parameterless choices remain in a separate group; choosing a behavior does not bypass the staged Apply boundary.
- Output choices include `OUT_NONE` (prevent output), `OUT_USB` (prefer USB), and `OUT_BLE` (prefer the current Bluetooth profile). `OUT_TOG` remains available. Apply, reopen, cancel, and Clipboard export retain the selected symbolic token.
- Key Toggle (`&kt`) uses the keycode picker, including modifier keys and hold wrappers; Apply requires a key. Grave Escape (`&gresc`), Soft Off (`&soft_off`), Reset (`&sys_reset`), and Bootloader (`&bootloader`) require no value but remain staged until Apply. Ctrl+click opens the stock behavior's ZMK documentation without changing the binding.
- The stock picker does not advertise `&reset`. Imported legacy `&reset`, including opaque arguments, is retained without conversion to `&sys_reset`; legacy JSON imports remain accepted. The editor's binding preview and no-op Apply retain complete opaque/excess arguments, not just the editable catalog slots.
- Users add blank layers, rename or delete layers, and undo/redo ZMK draft changes. Deleting a layer remaps supported layer references and combo filters, with a warning when a deleted target becomes transparent.
- In the expanded layer table with Stack off, Duplicate appends an independent copy of a layer's keys and encoder bindings, including layer zero. The first unused `<name> copy` / `<name> copy 2` name is chosen; copied self-references still target the original layer. Global combos/rules are not duplicated, and explicit combo filters do not gain the copy.
- Move opens a keyboard-accessible final-position selector; dragging a Move control onto another Move control uses the same transaction. Layer zero stays fixed. Proven reference targets follow their logical layers across bindings, combo filters, conditional rules, sensors and supported recipes; numeric firmware priority changes intentionally.
- Each successful duplicate/move is one firmware undo step. Duplicate retains focus on its source control; a move follows the moved layer's control. Cancel, Escape, unchanged position, rejected moves and external drops do not edit the document or consume redo. Results and refusal reasons appear in a polite status region. A move captured before another document edit is refused rather than retargeted.
- Users edit visual combos, conditional-layer rules and existing encoder sensor bindings. Hold-tap timing and Homerow/Autoshift presets are editable; the fixed rgblayer recipe can be inserted on save.
- Existing external bindings and their opaque parameters survive supported import/edit/export. Macros lists supported definitions and read-only diagnostics for opaque definitions; unsupported source is not promoted to editable syntax.
- Macros and Behaviors use the same compact outline chrome buttons as neighboring toolbar actions. Their named dialogs share the editor surface and a viewport-contained panel with internal vertical scrolling at 1280×720 and 360×640. Scrolling reaches longer content without expanding the modal shell; staged edits and source-preview confirmation remain separate from opening or closing a dialog.
- Macro list, sequence form, Text to sequence, invocation and source confirmation use the editor's light/dark control roles: ordinary 30px outline actions, danger-styled Delete/Remove, accent Confirm changes, inherited UI typography and themed fields. Disabled actions and fixed parameter counts remain visibly disabled; keyboard focus uses the accent outline. Compact groups and wrapping action rows keep long labels/diagnostics and confirmation text inside the panel at 1280×720 and 360×640. Single-line input values remain horizontally editable; source previews wrap inside their bounded scroller.
- Behavior list, family forms, ordered children, invocation and source preview use the same control roles and compact groups as Macros, with accent Apply changes distinct from firmware publication. Native checkboxes retain the accent checked/focus treatment; fixed existing types and unavailable actions remain disabled. Long labels, diagnostics and action rows fit the panel at 1280×720 and 360×640 in both themes; long forms scroll to later fields and actions. Tab skips disabled controls and stays in the dialog; Escape cancels staging and returns focus to Behaviors.
- Macros provides bounded staged authoring on Demo and verified Clipboard documents: create a label, edit display name, ordered behavior/control steps and tap/wait timing (including zero), then preview source and Confirm changes. New definitions offer zero, one or two parameters; existing parameter counts stay fixed. The focused interaction tests exercise one-input forwarding, step movement and timing, not every control combination.
- Use assigns a validated invocation to an existing key or combo with inferred argument types and a replacement/source preview. Delete refuses referenced or unproven targets and reports sites/reasons; an eligible unreferenced deletion also requires source preview and confirmation. Cancel and unchanged edits preserve redo. Confirmed changes carry the model and matching Clipboard source through firmware undo/redo; recovered Clipboard drafts retain that source for further editing and discard.
- Text to sequence requires explicit US QWERTY / ASCII acknowledgement and a valid sequence preview. It creates a new zero-parameter sequence, with editable initial tap/wait values of 40 ms, independently of Host language. Invalid input disables use rather than partially converting it; pasted CRLF is rejected before textarea normalization. Queue warnings remain visible during editing and confirmation.
- Applying a changed binding updates the firmware draft, not the source files. A dirty firmware draft arms native leave-page confirmation, including in Demo. Dismissing the confirmation keeps the applied edit; accepting it leaves without publishing.
- Behaviors lists named definitions and actionable read-only diagnostics. On Demo and verified Clipboard, New behavior and Edit stage bounded hold-tap, sticky-key/layer, tap-dance, mod-morph and zero-cell sensor-rotate definitions. The form exposes schema-specific decimal uint32 fields (zero is explicit; blank optional fields stay absent), flavor and presence flags, bare forwarded children or complete child invocations, and ordered tap-dance children. Existing type, node name and cell count stay fixed.
- The dialog states before Apply that definition edits are global to every reference, while arguments belong to individual key/combo/encoder invocations. Use validates inferred arguments and previews replacement of an existing key or combo; a sensor-rotate definition replaces a whole existing encoder adapter with no arguments, not one direction. It creates neither encoder hardware nor slots.
- Behavior edits, bindings and eligible deletion require source preview followed by Apply changes. Referenced deletion/rename and invalid definitions refuse without rewriting callers. Cancel/no-op preserves redo; applied source/model pairs survive undo/redo and Clipboard draft recovery. Interleaved macro and named hold-tap edits retain both models and legacy timing metadata. Actual Copy .keymap exports applied Clipboard changes; re-importing that DTS retains combo/key/encoder bindings and yields an identical unchanged subsequent export.
- Demo macro/behavior rename preflights the current generated definition graph, including when the editor-owned RGB recipe is present; the source-free writer rejects unresolved calls rather than exporting dangling references. Deleting an absorbed named hold-tap or preset removes its legacy timing mirror in the same staged transaction, retains other presets, and remains undoable.
- Demo layer duplicate/reorder supports pinned behaviors alongside the editor-owned RGB recipe, including repeated operations and typed layer-target remapping. Generated snapshots retain Demo provenance; exported RGB source imported through Clipboard does not gain definition-edit ownership.

## Rules and boundaries

- Core owns local help destinations, semantic categories (exact binding, family, recipe pattern) and their English hints. Code-only callers retain the exact allowlist; named-family resolution additionally requires a matching non-override document `holdTaps` entry with both child bindings, and refuses a matching opaque or non-hold-tap `behaviorDefinitions` entry. KeyEditorHost supplies the current document rather than inferring proof from catalog labels/arity/flags. Recipe help requires the explicit editor-owned selection context, not an arbitrary `&rgblayer_*` name. Lookup is not a network request, authoring permission, firmware compatibility check, module installation, OS configuration or device unlock. Documentation gestures do not publish or execute a binding. Native title discovery remains the existing desktop interaction; there is no new touch-help or custom tooltip workflow.
- Unicode compatibility checks editor-managed base outputs for digits, A–F, U, Space and Enter, not the active OS layout or firmware runtime. No fallback layout selection, mapping repair, OS detection/switching, or changes to `west.yml`, `.conf`, module `default-mode` or firmware setup occur. Existing source/header preservation remains separate; a compatible table does not prove module installation or mode-specific host input support.
- Primary firmware JSON containing `&hm` or `&as` as the leading binding label in layers, combos or sensor bindings requires a matching non-override `holdTaps` declaration; otherwise adapters fall back to raw DTS under ADR 0002. A same-label macro or behavior definition alone does not satisfy this dependency. Neither preset becomes stock; lookalike and malformed labels stay rejected, and other unknown labels still require the existing explicit source-import or declared-model allowance.
- Macro and behavior authoring are bounded, not arbitrary ZMK editors. Demo is positively source-free; Clipboard requires its matching source and core's closed source proof. GitHub/local, missing-source Clipboard, template-backed and unproven documents are not definition-authoring paths. No include fetching, repair, firmware build or host execution is added.
- Behaviors uses core's pinned schema subset, not every ZMK property. Sticky-layer is sticky-key with a bare layer child, not a separate compatible. Mod masks accept decimal literals, not expressions. Unsupported properties, opaque definitions, parameterized sensor adapters and unproven references remain read-only/source-preserved. Stock `&mt`/`&lt` override blocks are not named definitions and make behavior authoring unavailable under the existing coverage rule; their bytes are retained and existing key-editor timing/recipes remain separately owned. Review unsupported source externally and reload; there is no unsafe override or normalization.
- Macro Use supports keys and existing combos only: no sensor-child assignment or general sensor-adapter authoring, and no new hold-tap child authoring. Deletion/label rename require complete document-local reference coverage and zero incoming references; no cross-file proof or force-delete. The fixed rgblayer recipe stays separately owned. Macro-aware layer deletion and the full CHG-005 M01–M12 matrix are not certified by this slice.
- Text conversion accepts printable ASCII plus LF/TAB only, at most 24 characters / 48 queue entries, with a 16-entry margin against the pinned default queue size of 64. That margin is not a runtime safety guarantee; arbitrary concurrent/nested work, firmware settings, modifiers and host layout can affect output. No Unicode fallback or Host-layout inversion. General sequences retain core's 256-entry bound.
- Macro/behavior preview confirmation rechecks document/source identity and other open draft owners; stale previews refuse without overwriting newer work. Source and model travel together in existing browser history/recovery metadata, never through a UI serializer. Canonical visuals are schematics of separate states, not application screenshots or proof of firmware output.
- Duplicate/reorder accept Demo's positively source-free model or Clipboard's matching, supported source revision. GitHub, dev-local, source-less Clipboard, templates and unsafe/unknown source graphs are refused; controls do not bypass this boundary. Diagnostics direct users to review the source/definition externally. No include fetching or server expansion is involved.
- Opaque external arguments are not assumed to be layer indices. Reorder requires proven slots; duplication preserves opaque payloads only when the selected source/model passes preflight. Unverified includes, macros, aliases, overrides, partial parses and unsupported metadata refuse rather than silently regenerate source.
- Structural operations block while publication, host editing, staged definitions or registered key/encoder/combo/layer/macro drafts remain open. Apply rechecks guards. Supported source nodes, labels, comments and exterior bytes follow identity; appended DTS IDs use `layer_N` collision allocation, not the UI copy name. Raw Clipboard DTS re-import shows node names (for example `layer_4`), not the transient `Lower copy` name; JSON-first reload retains UI names. Clipboard textarea input normalizes line endings and the existing loader trims outer whitespace.
- Stock device commands only stage source bindings. They do not execute firmware actions, clear pairing information, disconnect a host, reset/power off hardware, or configure firmware. Output choices do not detect available transports; `OUT_NONE` is not power-off or bond clearing.
- Soft Off displays its prerequisite: `CONFIG_ZMK_PM_SOFT_OFF=y` in the keyboard `.conf`, hardware power-off support, and hardware-dependent wake-up (wake button or reset). The browser cannot establish firmware/hardware compatibility.
- Existing source splicing preserves the preamble; the stock catalog does not repair includes. Existing source must supply needed behavior/header includes; generated templates use catalog includes (`outputs.h` for `&out`, `keys.h` for `&kt`). The existing Unicode-specific include rule remains separate in ADR 0002.
- Selecting a replacement behavior intentionally replaces its old parameters. Opaque imports are preserved, not validated as stock firmware or exposed as a general custom editor. Neither deprecated `&inc_dec_cp` nor parameterized `RGB_COLOR_HSB(h,s,b)` is promoted to a new static picker choice.
- Source-preserving splice is bounded, not a full DTS/C preprocessor. Alias expansion is lossy as documented in ADR 0002; unsupported ambiguous edits can be rejected.
- Unicode and pointing firmware modules/configuration remain user responsibilities. The editor neither builds nor flashes firmware.
- Browser draft recovery is not publication. Source-specific write/copy/commit completion and native-dialog limitations follow [CAP-002](CAP-002-keymap-sources-and-persistence.md). Discard draft reverts firmware, not host-layout changes.
