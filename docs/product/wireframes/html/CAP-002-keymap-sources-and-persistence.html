Permission prompt — separate state

Grant write access

Grant write access is the required new gesture after identity proof. Its red attention treatment distinguishes the permission step from ordinary actions. Cancel / denial keeps the draft; a later attempt reselects the file.

Verified receipt

Firmware saved; host files not written. Close, full-byte readback and browser receipt commit all succeeded. Newer unsent edits remain dirty; this is not an OS install or all-work Saved.

Unresolved attempt — separate recovery state

Save not verified; file may have changed

Ordinary Save and firmware editing are blocked. A clean visible model does not resolve recovery.

Restore draftReconcile save

Restore only restores the draft. Reconcile reselects the exact file and checks dependencies and bytes, without opening a writable stream.

Intended bytes observed → Confirm reconcile from intended bytes / Cancel
Original bytes → retire matching attempt without writing
Other bytes / unreadable file → keep recovery protected

Confirmation accepts observed bytes, not retrospective success of a failed Save. No automatic retry, force overwrite or rollback.

Conflict / disconnected work — separate states

Open recoveryReconnectRestore draft

Stored work opens without disk access. Reconnect attaches freshly proved same-entry access even if disk content is unreadable/invalid; Reconcile save stays reachable and fails closed. Lost handles never rebind by name.

ReloadDiscard firmware draft and reload

Ordinary Reload refuses dirty/pending work. Destructive confirmation: discard the draft, retire the unresolved save attempt, and replace the verified baseline with validated disk bytes? This does not verify the earlier Save. No disk/host write; Cancel keeps recovery.
